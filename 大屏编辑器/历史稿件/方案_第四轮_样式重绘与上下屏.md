# 第四轮方案：样式不生效 / 容量来源 / 上屏下屏

> 2026-11-25 12:40　针对用户反馈的三个 bug。**本次先落方案再改，改完逐条实测。**

## 一、实测复现结果（不是猜的）

用 CDP 在纯净 localStorage 下造「3 张图表卡 + 1 张 KPI 卡」的自由布局，复现用户截图状态：

| 观察 | 实测值 |
|---|---|
| 容量 | `chartCap()=3`、`kpiCap()=1`（自由布局按画布卡数算，**数值是对的**） |
| 已上屏 | `1:bar 2:bar 3:histogram 10000:bar 10001:bar` → **5 张图挤 3 个位** |
| 点「饼图」后 selection | `type` 已从 `bar` 改成 `pie`（状态是对的） |
| 点「饼图」后大屏 series | **仍是 `bar`**，不重绘；手动 `renderScreen()` 才变 `pie` |
| 第 4、5 张图 | `renderScreen` 里 `if (!slot) return` **静默丢弃**，没有报错也没有提示 |

## 二、根因（对应三个 bug）

### Bug 1「配置不同样式，最终只有柱状图」
`onStyleClick / onDimClick / onAggClick` 只改了内存和列表行，**没有调用 `renderScreen()`**。
弹窗盖住大半屏幕，用户左边盯着大屏点样式，大屏从头到尾没变过 —— 观感就是"样式不生效"。
（渲染层本身没问题：14 种样式逐一实测都能画出对应图形。）

### Bug 2「图表数量限制」
限制**确实**来自布局：自动布局 = 列×行（A 型左右各一份），自由布局 = 画布图表卡数。数值对。
真正的缺口是两个：
1. `selItems` 可以超过容量而不报错（切换布局、老存档都会），多出来的选择在渲染时被静默丢弃 → 列表显示"图表 04"但屏幕上看不见。
2. UI 只写「图表位 3 个」，看不出这 3 是"自由布局画布上只画了 3 张图表卡"，用户不知道去哪加位。

### Bug 3「没有上屏/下屏」
上屏只能"点样式"隐式触发，下屏只能"再点一次同样式"，没有显式入口。
满位时 `makeRoom` 返回 false + 1.8s 高亮一闪而过，用户还没找到该关哪张，提示就没了。

## 四、不做的事（避免过度设计）

- 不自动顶掉用户已选图表（除了用户主动点「替换示例」那一下）。
- 不改渲染层的样式降级逻辑（2 维样式在只有 1 维时降级为柱状/折线，是既有设计；本次只让"选了就立刻能看见"）。
- 不动底部「已选清单」结构。

## 五、实施记录（2026-11-25 12:45）

全部按上表改完，`test29.js`（11 项）、`test30.js`（6 项）、`test23.js`（12 项回归）全过，0 报错。

改动过程中又挖出两个同源的老 bug，一并修了：

| 新增发现 | 现象 | 修法 |
|---|---|---|
| 自由布局下"上屏"不落卡 | 自由布局按 `freeLayout.items[].ind` 绑卡，新指标进池后没有任何卡绑它，`renderScreen` 只按 `sl.ind` 画 → 上屏了但屏幕上没有 | `renderScreen` 自由布局分支加补位：先在池子里找出"还没上卡"的图表/KPI，按顺序挂到空闲卡上（只改本次渲染的 `sl.ind`/`dataset`，不写回 `freeLayout`，弹窗取消能自动还原） |
| 确认后布局卡被删 | `pruneFreeItemsBySelection()` 用 `filter` 按 selItems 删卡：下屏一个指标再点确认，那张卡就永久消失，容量越用越小 | 改成只把失效绑定置 `null`（变待绑定卡），卡本身保留，容量稳定 |

### 关键实测数据

- 点「饼图」→ `selItems[].type=pie`，大屏 `series` 立刻从 `bar` 变 `pie`（修复前必须手动 `renderScreen` 才变）。
- 自由布局 3 图 1 KPI：`chartCap()=3`、`kpiCap()=1`，选 5 个时第 4/5 个标「超出 04 / 05」+ 顶部橙色「一键收起」。
- A 型 2 列×3 行×2 侧 = 12 位；切 B 型 2×2 = 4 位，容量立刻跟着变并自动裁剪超出项。
- 满位点「上屏」→ 提示条给「用「各区域就诊人次」替换示例「示例指标 A」」，点完 3/3 保持、示例 A 下屏、自定义上屏。
- 上屏/下屏点 × 仍然生效（`syncSelBackup`）；点样式点 × 会回滚（仍是草稿语义）。

## 六、收尾：取消语义统一（2026-11-25 14:30）

用户拍板「统一成弹窗里改什么都即时生效，× 只是关闭」。

**改了什么**

| 位置 | 改前 | 改后 |
|---|---|---|
| `closeModal()` | 用打开时的快照回滚清单/数据表/自定义指标 | 只关窗：落盘 + 重绘，不回滚 |
| `openModal()` | 拍快照 | 不再拍（`snapshotSel()` 保留为空实现，避免历史调用点报错） |
| `syncSelBackup()` | 同步快照 | 空实现 |
| 底部按钮 | 「确认选择」 | 「完成」（等价于关窗） |
| 关闭按钮 | 无提示 | `title="关闭（改动已即时生效，关闭不会撤销）"` |
| 已选清单提示 | 「也可直接确认」 | 「改完即时生效，还可再选 N 项」 |

**为什么不给"撤销"兜底**：上屏/下屏再点一次即还原；样式换回来只要一下；布局层面的改动本来就有 `Ctrl+Z` 撤销栈。「改错了能一步改回」比「改之前先确认」更符合操作直觉。

**验证**：`test30` T5 断言从"点 × 后回滚"改成"点 × 后保留且已落盘（直接读 localStorage `ds_selection_v2.byMenu[menu].items`）"，6/6 通过；`test23` 12/12 回归通过。
