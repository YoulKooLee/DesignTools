## 一、现状（我实际读到的代码，不是推测）

| 项 | 现状 |
|---|---|
| 底栏对齐控件 | `#dk-align` = **9 宫格小按钮**（18×13px），`alignEditorItems(h, v)` 9 种组合，每种**同时改 x 和 y** |
| 现有 9 种 | 左上 / 上中 / 右上 / 左中 / 正中 / 右中 / 左下 / 下中 / 右下 |
| 底层能力 | `alignEditorItems(h, v)` 内是 3 个独立 `if`（`h === 'left'/'center'/'right'`）+ 3 个独立 `if`（`v === 'top'/'middle'/'bottom'`）→ **天然支持只传一个轴、另一个传 null** |

| 冲突处理 | 对齐后**允许重叠**，仅在 toast 里提示「其中 N 张与其它卡片重叠」，不推挤邻居 |
| 撤销 | `pushEditorUndo()` 已有，一次对齐 = 一步撤销 |

## 二、根因：你要的是「单轴」，界面只给了「双轴组合」

你的 6 个词正好是标准两轴各 3 种：

| 你要的 | 只改哪个轴 | 现在能不能做到 |
|---|---|---|
| 左对齐 | x（全部左边缘对齐） | ❌ 只能点「左上/左中/左下」，会同时改 y |
| 右对齐 | x（全部右边缘对齐） | ❌ 同上 |
| 垂直（中线）对齐 | x（全部对齐到组内垂直中线） | ❌ 只能点「上中/正中/下中」，会同时改 y |
| 上对齐 | y（全部顶边对齐） | ❌ 只能点「左上/上中/右上」，会同时改 x |
| 下对齐 | y（全部底边对齐） | ❌ 同上 |
| 水平（中线）对齐 | y（全部对齐到组内水平中线） | ❌ 只能点「左中/正中/右中」，会同时改 x |

**结论**：不是底层算法缺失，是**入口缺失**。不用新写算法，只要能调 `alignEditorItems('left', null)` 这类单轴入口。

## 三、拍板结论（已定，按此实施）

### Q1 = 两套对齐各管一段，**不是同一功能的两种形态**

你原话：「这两个是不同功能，九宫格是固定位置的绝对对齐；后面这几个对齐是多选图表后相对对齐，以第一个选中的图表为基准进行对齐」。

| 套别 | 控件 | 参照系 | 一次改几个轴 | 归属 |
|---|---|---|---|---|
| **绝对/组合对齐** | 现有 9 宫格 | 选中组包围盒（单选=画布） | 同时改 2 个轴 | **完全不动**，一行代码不改 |
| **相对/单轴对齐** | 新增 6 个按钮 | **第一个选中的卡片**（`LE.selSet[0]`） | 只改 1 个轴 | 本次新增 |

→ 两套并存，互不覆盖；九宫格保留原语义、原位不动。

### Q2 = 按中线物理方向

| 按钮 | 边 | 只改 | 对齐公式（base = 第一个选中） |
|---|---|---|---|
| 左对齐 | `left` | **x** | `x = base.x` |
| 垂直（中线）对齐 | `xmid` | **x** | `x = base.x + (base.w - w) / 2` |
| 右对齐 | `right` | **x** | `x = base.x + base.w - w` |
| 上对齐 | `top` | **y** | `y = base.y` |
| 水平（中线）对齐 | `ymid` | **y** | `y = base.y + (base.h - h) / 2` |
| 下对齐 | `bottom` | **y** | `y = base.y + base.h - h` |

→ 每组 3 个按钮只改一个轴，另一个轴的坐标**一个像素都不动**，可直接断言验证。

## 四、实施清单（每条：改哪里 → 怎么改 → 怎么验收）

### P0　新增单轴相对对齐函数

- **改哪里**：`alignEditorItems()`（L5967）下方新增 `alignEditorItemsToFirst(edge)`
- **怎么改**：
  - `edge` ∈ `left | xmid | right | top | ymid | bottom`
  - `base = LE.items[LE.selSet[0]]`；目标 = `selSet.slice(1)` 的全部卡片
  - 只算一个轴的新值，另一轴沿用原值；`clampNum` 防出界
  - 无变化时给「已经与基准对齐」提示，不写撤销栈
  - 有变化时 `pushEditorUndo()` → 改坐标 → `paintEditorAll()` → `renderEditorDock()`
  - 末尾查组外冲突，有压叠只警告不推挤（与九宫格一致）
- **验收**：6 个方向各跑一遍，断言目标轴全部等于基准对应边/中线、非目标轴零变化、撤销一步回滚

### P1　UI：6 个单轴按钮（内联 SVG 图标）

- **改哪里**：底栏 DOM（`<span class="dk-lab">对齐</span>` 之后）+ CSS（`.dk-grid` 之后）
- **怎么改**：
  - 新增 `#dk-axis`（class `.dk-axis`），顺序：`左 | 垂直中线 | 右 ‖ 上 | 水平中线 | 下`，中间一条分隔符
  - 每个按钮 24×20，图标用**内联 SVG**（18×14：黄色基准线 + 两个灰蓝方块），不引外部资源、不加网络依赖
  - `title` 写明轴向，例：「左对齐到基准卡（只改 X，Y 不动）」
  - 需要选中 ≥2 张才启用（相对对齐本质上需要基准 + 至少一个目标）
- **验收**：未选/单选时 6 个灰化，选中 2 张即点亮；tooltip 含「只改 X / 只改 Y」

### P2　基准卡视觉标记（不做沉默处理）

- **改哪里**：`.le-item` CSS 附近 + `paintEditorSelection()`
- **为什么必须做**：`sel-main` 高亮标在**最后**点的卡上，但基准是**第一张**。不标出来用户必按错对象。
- **怎么改**：`paintEditorSelection()` 里给 `LE.selSet[0]` 加 `sel-base` class（仅多选时）；CSS 给基准卡加**黄框**并把「基准」标签放在**卡片上边缘外侧**（`top:-17px`），既不遮标题也不遮图表
- **验收**：多选 3 张时，第一张黄框 + 外侧「基准」标、最后一张仍保留 `sel-main` 亮边，两者可同时存在

### P3　提示文案按轴向区分

- **改哪里**：`alignEditorItemsToFirst()` 内 toast
- **怎么改**：文案形如「左对齐 3 张 → 基准：示例指标 A（只改 X）」；出界被钳制时追加「N 张已贴到画布边缘」
- **验收**：6 个按钮文案各不相同且含轴向说明，不出现含糊的「已对齐 N 张」

### P4　三轨验证 + 清理

1. **逻辑轨**：3 张不同尺寸卡片，6 个方向各断言「目标轴全等基准 + 非目标轴零变化 + 出界钳制 + 撤销回滚」
2. **交互轨**：真实 Chrome 打开自由布局编辑器 → Shift 多选 3 张 → 逐个点 6 个按钮 → 读 `LE.items` 坐标 + `JS_ERRORS=0`
3. **截图轨**：6 个方向各截一张放大裁切，目视对齐结果、基准角标、按钮启用状态
4. **回归**：9 宫格 9 种组合、水平/垂直等距、一键排版、KPI 横排全部重跑，确认零回归

## 五、边界与不做的部分

- **九宫格一行不改**：它是「绝对/组合对齐」，与本次新增的「相对/单轴对齐」是两套功能
- **新按钮参照系固定为第一个选中**：不做「对齐到画布」开关，避免同一排按钮出现两套参照系
- **允许重叠**：与现状一致，压到组外卡片只提示不推挤（推挤会连环改别人位置）
- **不动算法**：`tidyEditorLayout()`、`alignInPlace()`、`layoutKpiRowInTidy()` 一律不动
- **不改存档结构**：纯前端交互，无新 localStorage key
