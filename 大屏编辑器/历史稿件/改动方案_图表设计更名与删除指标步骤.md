## 二、删除「② 指标」步骤

### 核实结论：你的判断成立

②指标面板（`renderIndicatorPanel`，4515–4542 行）的全部内容：

| ②里的东西 | 实际行为 |
|---|---|
| 指标列表统计（内置 X 条 · 自定义 Y 条） | 纯展示 |
| 「+ 新建指标（进入维度计算配置）」按钮 | 只是跳到③维度计算（`startNewIndicator` → `switchModalTab('calc')`），②本身零配置 |
| 自定义指标列表「编辑」按钮 | 也只是跳到③（`editIndicator`） |
| 自定义指标列表「删除」按钮 | **真删除，这是②独有的功能** |

即②作为向导步骤确实多余——所有配置动作都发生在③。唯一不能直接丢的是「删除」入口。

### 改法（4 处）

1. **删标签**（744 行）：步骤条变 3 个：`① 数据`、`② 维度计算`、`③ 图表`（顺延重编号）。
2. **删面板 div**（753–754 行）与 `switchModalTab` 里 `tab==='indicator'` 分支（4275 行）。
3. **自定义指标管理并入③**：`renderCalcPanel()` 渲染时，在步骤条卡片下方固定追加一张「自定义指标」卡（复用 `renderIndicatorPanel` 里 4524–4540 的列表 HTML 逻辑，含编辑/删除按钮）。空态显示「暂无自定义指标 + 新建指标按钮」。
4. **修文案与回跳**：
   - 4632 行空态文案「请到『② 指标』点新建」→「点下方『新建指标』开始配置」；
   - 4847 行 `cancelCalcDraft` 取消后回跳 `indicator` → 改为留在 `calc`（此时正好显示指标管理列表）；
   - `renderIndicatorPanel`、`deleteIndicator` 里的调用改为刷新③面板。

### 风险与边界

- 删除自定义指标时「已上屏卡片一并移除」逻辑不变，只是入口挪到③。
- ②面板删除后，`startNewIndicator` 无数据表时的提示「到『① 数据』导入」仍成立，不改。

## 三、③维度计算 5 个子步骤核对

子步骤定义（4573 行）：`选事实表 → 标字段角色 → 定聚合方式 → 时间粒度/范围 → 真算预览`。

| 子步骤 | 实际承载 | 覆盖的核心动作 |
|---|---|---|
| 1 选事实表 | 选表 + **指标名称/单位/模块**（4654–4656 行） | 定数据源 + 给指标命名 |
| 2 标字段角色 | 每列选 分类维度/时间/度量，导入时自动推断可改（4662–4678 行） | 字段角色标定 |
| 3 定聚合方式 | 度量字段、汇总方式（求和/均值/计数等）、小数位、统计维度（≤2，超限拦截）、图表样式按维度数过滤（4682–4736 行） | 统计口径定死 |
| 4 时间粒度/范围 | 时间列归桶粒度（按日/月/年自动匹配取值）；范围=全量（原型限定，4755 行明示） | 时间口径 |
| 5 真算预览 | 真实聚合结果表（参与行数/跳过行/文本数字解析），「保存指标并上屏」（4760–4796 行） | 验证 + 落地 |

**结论：核心链路（选表→命名→定角色→定口径→时间粒度→预览→保存）全部涵盖，无缺口，不需要增补子步骤。** 一个已知小怪癖：编辑已有指标时直接落在第 4 步（`initCalcDraft` 4578 行 `step: 4`），可用但入口略深，本次不改（超出你提的范围，如要改另说）。
