## 二、需求拆解：目标链路

理解的用户意图（一条闭环）：

```
① 导入数据（手动添加 / 批量导入）
      ↓
② 指标管理：指标列表 → 指标配置 → 维度计算配置（选事实表 / 维度 / 度量 / 聚合）
      ↓
③ 真算：aggregateBy 按配置聚合明细数据
      ↓
④ 生成图表 → 进入「已选清单」→ 上大屏卡片
```

即：大屏图表从「hash 随机数」升级为「导入数据 + 维度计算配置真算」，且把指标平台四模块以可用的精简形态搬进大屏。

### 9.3 D3 勘误：原型里不存在「四个并列模块」

「指标管理 / 指标列表 / 指标配置 / 维度计算」是**一条纵向链路**，不是四个平级模块；「四模块」是初稿沿用用户原话造成的不严谨归纳。以 `index.tsx` 的 `defineHashPageRoute` 与各页面文件为真源：

| 词 | 真实身份 | 真源位置 | 能否独立成模块 |
|---|---|---|---|
| 指标管理 | **菜单分组 group**，下挂 8 个页面 | `index.tsx` L37–44 `group: '指标管理'` | 否，是容器 |
| 指标列表 | 分组下**页面** `indicator-list` | `pages-indicator.tsx` | 是 |
| 指标配置 | 分组下**页面** `indicator-config` | `pages-indicator-config.tsx`（3 步向导） | 是 |
| 维度计算 | **不是菜单项**，是「指标配置」里生成规则 `RuleKind` 的一个取值 | `pages-indicator-rule.tsx` L13 `RuleKind = 'SQL开发' \| '维度计算'` | 否，是配置内的规则类型 |

「维度计算」展开后是 **5 步配置流程**（选事实表 → 标字段角色 → 度量计算方式 → 时间粒度与范围 → 预览），横跨 `pages-indicator-rule.tsx`（配置）、`dim-calc-preview.tsx`（第五步预览）、`dim-calc.ts`（`aggregateBy` 真算内核）、`pages-indicator-chart.tsx`（列表行「图表预览」弹窗）。**它自身没有 4 个模块**，用户质疑成立。

**通用设计器下的重组建议**（按「能力」而非「菜单层级」切 4 个面板，弹窗内标签页）：

| 面板 | 承载 | 对应原型 |
|---|---|---|
| ① 数据 | 导入/管理明细事实表、字段角色标注 | 数据源 + `pages-indicator-rule` 第 1–2 步 |
| ② 指标 | 指标列表 + 新建/配置（名称/单位/来源表/图表类型） | `pages-indicator.tsx` + `pages-indicator-config.tsx` |
| ③ 维度计算 | 维度(≤2) / 度量 / 聚合 / 时间粒度 / 真算预览表 | `pages-indicator-rule.tsx` + `dim-calc-preview.tsx` + `dim-calc.ts` |
| ④ 图表 | 样式过滤、生成、已选清单、上屏 | 现有「选择图表」弹窗 |

### 9.4 D4 可行性评估：有数据真算 / 无数据随机数

**结论：可行，且比「全量替换随机数」更稳。** 原稿 D4 推荐「真算替换随机数，未配置指标保持示例数据」与用户表述是同一策略，用户表述更精确（显式 fallback）。

**落点（两处分支，其余不动）**：

| 函数 | 现状 | 改造 |
|---|---|---|
| `buildOption(d, type, dims)` (L1989) | 全部走 `OPT_BUILDERS` / `OPT_BUILDERS_2D` 随机数 | 开头加分支：`d.datasetId` 命中 `DATASETS` → `buildOptionFromDataset()`；否则**原逻辑原样执行** |
| `kpiValueOf(d, agg)` (L1297) | `rngOf` 造数，`avg` 按 /12 | 同上加真算分支；无 dataset 保留 /12 模拟 |

随机数链路本身**就是 fallback**，一行不用改 —— 这是该策略最省事、最不易回归的地方。真算内核 `aggregateBy`（sum/avg/count/max/min）从 `dim-calc.ts` 去 TS 类型后移植，无 React 依赖。

**唯一硬风险：清理边界。** 随机数造数依赖 `IND` 的 `unit/cat/time/cats` 与 `UNIT_RANGE`(L1272)、`FAM_CATS` 维度字典(L1209)、`hashStr/rngOf`、`RELATIONS`、`OPT_BUILDERS`。若「数据清理」把它们一起清掉，**「无数据用随机数」会失效**（没有类目、没有量程）。故清理必须分级：

### 11.6 「选折线却画成柱状」缺陷修复（2026-11-24 追加）

**用户反馈**：`我选择图形是分组折线图，出来的实际是柱状图`

**复现**（无头 Chrome + CDP，按真实控件点击，非直接改状态）：

| 操作序列 | 修复前 `chartType` | 修复后 |
|---|---|---|
| 勾「区域」(1 维) → 选「折线图」→ 补勾「日期」(第 2 维) | `stackBar`（堆叠柱状图，静默替换） | `lineMulti` |
| 2 维选「多系列折线」→ 取消「日期」→ 再勾回 | `bar` → `stackBar` | `line` → `lineMulti` |
| 0 维（全表）指标配 `lineMulti` 出图 | `series=[bar]` | `series=[line]` |

**根因（两处，同属「样式状态被静默改写」）**：

1. `renderCalcPanel()` 第 3 步样式下拉每次重绘都有兜底行：`if (!styles.some(s => s.key === C.chartType)) C.chartType = styles[0].key`。维度档位从 1 变 2 时，`line` 不在 2 维档位里，于是被直接替换成该档第一个 `stackBar`；反过来 2 维取消维度也会丢成 `bar`。用户已经选好的样式被静默改写，保存上屏就变柱状。
2. `buildOptionFallback()` 用 `OPT_BUILDERS[type] || optBar` 取渲染器。`lineMulti / groupBar / sunburst / heatmap` 都属于 2 维渲染器，在只有 1 维（或 0 维）可用时 `OPT_BUILDERS[type]` 是 `undefined`，直接掉到 `optBar`，折线被画成柱状。

**修复**：

- 第 3 步样式兜底改为**同族迁移**：优先 `need===2 ? UP_2DIM[C.chartType] : DOWN_1DIM[C.chartType]`（折线→多系列折线、面积→多系列折线、饼→旭日、柱→分组柱），迁移目标不在当前档位才回落该档第一个。
- 渲染器兜底改为 `OPT_BUILDERS[type] || OPT_BUILDERS[DOWN_1DIM[type]] || optBar`，两维样式在低维场景按同族降维，不再掉柱状。

**验证**（同一套 CDP 脚本，10 项断言）：`补齐第 2 维后仍为多系列折线 ✓`、`保存后 calc.chartType=lineMulti ✓`、`上屏卡片 type=lineMulti ✓`、`渲染出 6 条 line 系列（区域×月份）✓`、`刷新页面回读存档后仍为折线 ✓`、`JS_ERRORS=0 ✓`；截图目视主屏「区域月份走势」为 6 条彩色折线（带圆点与图例），非柱子。

**未改动边界**：随机数兜底链路的 1 维样式（`bar/line/pie/…`）行为零变化；两维真算与聚合内核未动；1/2 维自动迁移规则复用既有 `UP_2DIM` / `DOWN_1DIM` 常量，未新增映射表。

### 11.7 「选雷达图却画成柱状」— 真算样式矩阵补齐（2026-11-24 追加）

**用户反馈**：`我选择生成雷达图，结果出来的是柱状图，你最好挨个检查下`

**根因（比 11.6 更底层）**：`buildOptionFromDataset()` 的一维分支原来只有三条出路 —— `isPie → pie`、`isLine → line`、其余一律 `bar`。也就是说真算模式下，**雷达图 / 条形图 / 排行榜 / 面积图 / 瀑布图 / 直方图 全部静默画成柱状图**，二维**旭日图**同样落进 `bar` 分支。11.6 修的是「样式被改写」，这一条是「样式没被改写、但渲染器不认」。

**补齐矩阵**（真算渲染器）：

| 维度 | 样式 | 渲染实现 |
|---|---|---|
| 1 维 | `bar` | 纵向柱（原逻辑） |
| 1 维 | `barH` | 横向条 + 右置值标签，类目保持原序 |
| 1 维 | `rank` | 横向条，按值降序取前 12，逐位配色 |
| 1 维 | `radar` | 类目=雷达轴（前 8 个），单系列多边形 + 半透明填充 |
| 1 维 | `line` | 折线（原逻辑） |
| 1 维 | `area` | 折线 + 面积填充 |
| 1 维 | `waterfall` | 占位系列 + 值系列堆叠，逐项累加、末根为累计（涨红跌绿） |
| 1 维 | `pie` | 饼图（原逻辑） |
| 1 维 | `histogram` | 取度量列**原始值**分箱计数（箱数 ≈ √n，限 4–12），y 轴标「条数」 |
| 2 维 | `groupBar` / `lineMulti` / `stackBar` / `heatmap` | 原逻辑（已正确） |
| 2 维 | `sunburst` | 新增：真算结果直接组两级树（内环=维1，外环=维2） |

**同时收紧可选范围**：新增 `DS_STYLES` 白名单 + `dsStylesForDims(n)`。真算下无法真实表达的 4 种样式从自定义指标的样式下拉与行内 chip 中移除 —— 箱线图（需原始分位数）、散点图/气泡图（需两个度量）、桑基图（需流向关系）。内置中性示例指标（随机数链路）不受影响，仍可选全部 16 种。

**一致性加固**：`normalizeItemObj()` 对自定义指标补上「样式 ↔ 维度个数」对齐（2 维配 1 维样式会少画一个维度 → 按 `UP_2DIM` 迁移；1 维配 2 维样式 → `DOWN_1DIM` 降档），不再出现「配置了 2 个维度、图里只画 1 个」。

**验证（逐个样式，22 项断言全绿）**：`1D=bar,barH,radar,line,area,waterfall,pie,histogram,rank` / `2D=stackBar,sunburst,heatmap,groupBar,lineMulti`；每个样式的 `series[].type`、坐标轴方向（`barH`/`rank` 必须是 y 类目轴）、堆叠标记（`stackBar=total`、`waterfall=wf`）、`area` 面积样式、`rank` 降序、`histogram` 箱数与「条数」轴名逐项核对；真实 UI 选雷达图保存后 `calc.chartType=radar`、卡片 `type=radar`、ECharts 实际 `series=[radar]`；截图目视雷达图为六边形蛛网 + 区域A~H 轴标签 + 填充块，非柱子；`JS_ERRORS=0`。
