## 一、它是什么

一个**单文件、离线、双击即用**的大屏设计器。整个产品就是一个 HTML 文件：图表引擎、三维地图底图、全部样式和逻辑都封在里面，拷到任何一台电脑上用浏览器打开就能跑，不装服务、不连数据库、不联网。

它要解决的是三件具体的事：

| 痛点 | 传统做法 | 这个编辑器的做法 |
|---|---|---|
| 换一个统计口径就要改一次报表 | 找开发改 SQL、发版 | 界面上勾几下，几秒钟出新图 |
| 大屏位置全靠手工摆 | 一个个拖、一个个量 | 按画布尺寸自动算出每张卡该在哪 |
| 给领导演示时数据是编的 | 用假数据糊过去 | 导入真实明细表，现场算真数 |

## 二、一张图看懂全链路

做一张大屏，本质上是在回答四个问题。编辑器把这四个问题做成了四级流水线，**左边一改，右边立刻重画**。

```
① 数据            ② 指标              ③ 维度              ④ 图形
有什么原始记录  →  要算哪个数      →   按什么切开看     →   画成什么形状
（明细事实表）     （度量＋聚合）       （分组＋粒度）        （图表样式）

  768 行明细    →   "就诊人次求和"  →   "按区域×按月"    →   分组柱状图
```

每一级只干一件事，且都能单独替换：换数据不用重配图，换图不用重导数据，加一个维度会自动切换成能画两个维度的样式。

下面逐级讲。

## 三、先把术语说清楚

这套东西的所有困惑，几乎都来自"维度"和"度量"这两个词没对齐。先用一句话锁死：

> **度量是"要算的数"，维度是"按什么分开算"。**

| 术语 | 大白话 | 在编辑器里的体现 |
|---|---|---|
| **明细事实表** | 一行一条原始记录的表，最细的那一层 | 导入的那张 CSV / 粘贴的那片 Excel 区域 |
| **字段角色** | 每一列在计算里扮演什么身份 | 每列会被标成"分类维度 / 时间 / 度量"三者之一 |
| **度量** | 可以被加总、平均、比大小的**数值**列 | 就诊人次、费用、满意度 |
| **维度** | 用来**切分**数据的**类别**列，本身不代表大小 | 区域、机构、业务类别、月份 |
| **聚合** | 把很多行的数值压成一个数的算法 | 求和、平均、计数、最大值、最小值 |
| **指标** | 度量 + 聚合 + 一个名字，得到的一个可展示的数 | "本月就诊人次" |
| **粒度** | 时间切多细：按小时、日、周、月、年 | 日期列下方那个下拉框 |
| **基数** | 一个维度有多少个不同取值 | "区域"基数是 8，"单据号"基数是 768 |
| **KPI** | 不切片的指标——整张表只出一个数 | 顶部横排那一行大数字卡 |
| **图表带** | 屏幕上留给图表的矩形区域 | A 型布局里分左右两条带 |
| **三维区** | 留给地图 / 三维场景的中心区域 | 大屏正中那块深色场景 |
| **逻辑像素** | 设计时使用的"标准尺寸"，与实际屏幕无关 | 画布宽 1600–4000 可调，高固定 900 |

关键区别再强调一遍，因为这直接决定了后面所有规则：

- **维度不能求和。** "华东 + 华南 + 华北"在业务上没有意义；
- **度量不能直接当分组。** 拿"费用 = 3250 元"当一类，等于每一行自成一类，图上会出现几千个柱子。

编辑器判断一列是维度还是度量，靠的是**内容本身**，而不是列名：抽样前 60 个非空值，能被解析成数字的比例 ≥ 80%，就认定为度量列；形如 `2026-11`、`2026/11/24`、`2026-11-24 10:30` 的，认定为时间列；剩下的都是分类维度。导入时会自动标注，标错了可以一键改。

## 四、第一级 · 数据：为什么必须是明细

### 4.1 明细是唯一"还能再切"的形态

一张已经汇总好的表，比如"各区域月度就诊人次"，看起来省事，但它把切分方式**焊死**了。想改成按机构看？没有机构这一列，只能回去重新导。

明细表没有这个问题：所有切分方式都还留在原始行里，随时可以重切。

```
明细表（能切）                     汇总表（切不动）
区域  机构  月份   人次            区域   人次
华东  甲院  01月   120      →      华东   720
华东  乙院  01月    95             华南   540
华南  甲院  01月   ...
```

代价是行数变多，而这件事对编辑器无感——768 行全表解析 + 分组聚合，耗时在毫秒级。

### 4.2 一张合格的明细表长什么样

三条要求，缺一条就会算错：

1. **首行是表头**，每列一个明确的名字；
2. **一行代表一次业务发生**，不要在行里做小计、合计、空行；
3. **数字就是数字**，不要写成 `1,250元`、`约 300`。编辑器能容错千分位和全角数字，但夹了文字的会算不出来。

示例（真实可跑的测试表结构，768 行）：

| 单据号 | 区域 | 机构 | 业务类别 | 日期 | 就诊人次 | 费用 | 满意度 |
|---|---|---|---|---|---|---|---|
| D0001 | 区域A | 甲院 | 门诊 | 2026-01-05 | 42 | 3180 | 92 |
| D0002 | 区域H | 乙院 | 住院 | 2026-03-18 | 17 | 8650 | 88 |

这张表刻意放了一个**高基数字段**（单据号，768 行 768 个不同值）用来验证"这种列不会被误当成维度"，后面讲维度判定规则时会用到它。

### 4.3 导入的三条路

| 方式 | 适用场景 | 说明 |
|---|---|---|
| 直接粘贴 | 手上有一段 Excel 区域 | 从 Excel 复制，粘进文本框，自动识别逗号 / Tab / 分号 |
| 选文件 | 已有 CSV / TXT / TSV | 本地读取，文件不上传任何服务器 |
| 手动录入 | 临时演示几条 | 逐行敲，适合做样例 |

三种方式共用同一套解析器：去 BOM、处理引号内的分隔符、剔除空行、表头重名自动加后缀。**没有任何第三方解析库**，全部自己实现，这是"单文件离线"的前提。

### 4.4 脏数据的四条护栏

真实数据一定是脏的。处理原则是**宁可少算，不可错算**——不把缺失当 0，因为 0 会拉低平均值、会让趋势线出现假谷底。

| 情况 | 处理 | 界面上会提示 |
|---|---|---|
| 数值列出现 `N/A`、`—`、`无`、空串 | 该行**跳过**，不参与计算 | 跳过 N 行无效数值 |
| 维度值为空 | 该行**跳过**（无法归入任何一组） | 跳过 N 行空维度 |
| `1,250`、`１２５０`（全角）、` 1200 ` | 清洗后按数字解析 | 解析 N 行文本型数字 |
| 数值是负数 | 正常保留（退款、冲销是真实业务） | 不提示 |

## 五、第二级 · 指标：一个数是怎么算出来的

### 5.1 指标的定义式

任何一个指标，都可以写成这个式子：

```
指标(S) = 聚合函数 { 度量值(r) | r ∈ S }
```

其中 S 是"被挑出来的那些行"。这句话翻译成人话：**先圈定一批行，再把这批行的某个数值按某种方式压成一个数。**

圈定的方式不同，就得到不同的指标：

| S 的范围 | 得到什么 |
|---|---|
| 整张表所有行 | 一个 KPI（全场一个数） |
| 每个区域各自的行 | 一张区域对比图（8 个柱子） |
| 每个区域 × 每个月的行 | 一张区域月度交叉图（48 组） |

### 5.2 五种聚合，公式与适用场景

设某个分组下有 n 行，度量值分别为 m₁, m₂, …, mₙ：

| 聚合 | 公式 | 什么时候用 | 注意 |
|---|---|---|---|
| 求和 | `m₁ + m₂ + … + mₙ` | 总量型：人次、金额、件数 | 默认值；同组相加有业务意义才用 |
| 求平均 | `(m₁ + … + mₙ) / n` | 比率型：满意度、平均住院日 | n 是**有效行数**，无效行已剔除 |
| 计数 | `n`（行数） | 事件次数：报了多少单、发生几次 | **文本列也能数**，这是它和求和的本质区别 |
| 最大值 | `max(m₁ … mₙ)` | 峰值：最高单日门诊量 | 不受异常小值干扰 |
| 最小值 | `min(m₁ … mₙ)` | 谷值：最短响应时长 | 同上 |

"计数按行数算"这条规则很重要：它让**任何**一列都能变成指标。比如"异常事件"这一列是文字描述（"跌倒""给药错误"），不能求和，但能数出发生了多少次——这在质控类大屏里比求和更常用。

配套的还有两个显示规则：

- **小数位** 0–3 位可选，只影响显示，不参与计算（避免连续四舍五入累积误差）；
- **大数缩写**：绝对值 ≥ 1 亿显示"亿"，≥ 1 万显示"万"，保留两位小数。20 万比 200000 更快被读出来。

### 5.3 五步配置，一步一校验

配一个指标是五步，每步都能回退，第 5 步直接出预览表：

| 步骤 | 做什么 | 卡点 |
|---|---|---|
| 1 · 选事实表 | 指定用哪张明细表 | 没有表就先提示去导入 |
| 2 · 标字段角色 | 确认每列是维度 / 时间 / 度量 | 已自动推断，这里只做修正 |
| 3 · 定聚合方式 | 选度量列 + 聚合方式 + 维度（最多 2 个）+ 样式 | 维度超 2 个、度量不完整会拦住 |
| 4 · 时间粒度与范围 | 选归桶粒度 | 没选时间列就跳过这一步 |
| 5 · 真算预览 | 看实际算出来的前 20 组 | 展示参与行数、分组数、各类跳过数量 |

第 5 步是这套设计的关键：**在图上屏之前，先用表格把数字摆出来**。分组数对不对、有没有大面积跳过、平均值是不是被异常值带偏，看一眼表就知道，不用等图画出来再猜。

## 六、第三级 · 维度：把一张表切成很多格子

### 6.1 分组的本质是一个乘法

选了 k 个维度，每个维度的不同取值个数（基数）是 c₁, c₂, …, cₖ，那么最终会切出多少个组：

```
分组数 = c₁ × c₂ × … × cₖ
```

这是一条**乘法**关系，也是大屏最容易踩的坑。示例表里：8 个区域 × 4 个业务类别 = 32 组，还勉强；换成"区域 × 月份"就是 8 × 6 = 48 组；如果允许三个维度齐上，8 × 4 × 6 = 192 组——屏幕上根本放不下，柱子会细成发丝。

这正是"维度最多选 2 个"这条硬规则的全部理由：**不是技术做不到，是屏幕画不下**。

### 6.2 一个维度能不能用：两条判据

编辑器对每一列都做一次体检，两条判据任一不通过，这个维度就会被禁用（勾选框变灰、标"超限"）。

**判据一 · 类目数上限**

```
C = 该列不同取值的个数（去重后的非空值）
若 C > 30  →  不可作为维度
```

理由：一屏图表横向最多容纳 30 个刻度还能读清；饼图超过 30 个扇区，人眼已经无法比较面积，只能靠颜色猜。

**判据二 · 近似唯一性**

```
若 C / N ≥ 0.9  且  全表行数 > 30  →  不可作为维度
其中 N = 该列非空值的行数
```

这条针对的是"看起来像维度、实际是编号"的列。单据号在 768 行里有 768 个不同值，比例是 1.0，远超 0.9——它一旦被当成维度，每个柱子只有 1 行数据，图就退化成了"把原始表逐行贴到屏幕上"，毫无意义。判据二把它拦住。

两条都通过，这个维度才可选。示例表里的判定结果：

| 字段 | 基数 C | 判据一（>30 拦） | 判据二（近似唯一拦） | 结论 |
|---|---|---|---|---|
| 区域 | 8 | 通过 | 8/768 ≈ 0.01 | ✅ 可用 |
| 业务类别 | 4 | 通过 | 0.005 | ✅ 可用 |
| 机构 | 未超 30 | 通过 | 比例极低 | ✅ 可用 |
| 单据号 | 768 | ❌ 超限 | ❌ 比例 1.0 | ⛔ 禁用 |
| 费用 | 取值众多 | ❌ 超限 | — | ⛔ 禁用（且它本身是度量列） |

### 6.3 时间维度：粒度是把连续时间折叠成桶

时间是特殊的维度——它的取值可以无限细分，所以必须先决定"切多细"，这个动作叫**归桶**。

| 粒度 | 归桶规则（等价于取哪一段字符） | 效果 |
|---|---|---|
| 按小时 | 保留到 `年-月-日 时` | 一天 24 个点，看日内波动 |
| 按日 | 保留到 `年-月-日` | 默认档，最细的日常粒度 |
| 按周 | 先找到该日期所在周的**周一**，用周一的日期代表这一周 | 消除周末双休造成的锯齿 |
| 按月 | 截取 `年-月` | 大屏主力口径，一年 12 个点 |
| 按年 | 截取 `年` | 跨年对比，点多时用 |

按周的计算要注意：直接取"周数"会在跨年时错位（第 1 周可能被劈成两段）。这里用的是**算周一、用周一日期代表**，任意相邻两天只要在同一自然周，就必然落到同一个标签上，不会错位。

粒度选项不是写死的，而是**按真实数据分布推出来的**：

```
抽样 40 个取值
· 全部只有"年"        → 只给【按年】
· 全部只到"月"        → 给【按月、按年】
· ≥50% 带具体小时      → 给【小时、日、周、月、年】全档
· ≥80% 到具体某天      → 给【日、周、月、年】
· 其他                → 给【日、月、年】
```

道理很简单：数据只到月，硬选"按日"只会得到 30 个标签全挤在月末那一天；数据带小时，却只给到"月"，就浪费了信息。

### 6.4 分组之后，顺手做一次体检

算完会输出一行统计，这行字是排查数据问题的第一现场：

```
参与 768 行 · 分组 48 个 · 跳过 0 行无效数值 · 跳过 0 行空维度
```

（如果原始表里的费用写成 `3,180` 这种带千分位的形式，这里会多出一项"解析 N 行文本型数字"。）

- **参与行数** 明显小于总行数 → 说明度量列大面积无法解析，多半是选错了列；
- **分组数** 远超预期 → 检查是不是混进了高基数字段；
- **跳过行数** 不为 0 → 检查维度列有没有空白单元格。

### 6.5 指标有两个独立属性：算什么，和长什么样

这是被误解最多的一处，必须单独说清。一个指标在屏幕上的呈现，由两个**互相独立**的属性决定：

| 属性 | 取值 | 谁决定 | 换掉会怎样 |
|---|---|---|---|
| 数据集（算什么） | 某个自定义计算 / 某条示例数据 | 配置时就定死 | 换掉等于换了一个指标 |
| 展示形式（长什么样） | KPI / 柱 / 折线 / 饼 / 环形… | 上屏后随时可改 | 只换形状，数字不变 |

分开的理由是使用场景不同：**算口径**是配置期的事（偶尔做一次，要想清楚），**换形状**是排版期的事（经常做，看哪里挤了就换）。

如果两者绑在一起，"把它改成饼图"就等于要重配一遍指标，没人愿意干。

### 6.6 示例指标只给"隐藏"，不给"删除"

内置示例是代码里带着的，清一次浏览器缓存就会复活。如果按钮写着"删除"，用户删完发现它又回来了，会认为工具在骗人。

所以示例指标的动作是**隐藏**（`隐藏` / `恢复已隐藏示例（N）`），语义是"我不想在这份清单里看到它"，这个意图是可持续的。自定义指标才是真删除——因为那份数据确实只存在于本机。

## 七、第四级 · 图形：从数值格子到一种形状

### 7.1 选图的原则是"要表达什么关系"

不是"这个图好看"，而是"这个图能不能最准确传达数据关系"。同一个数据集，想说的话不同，正确的图就不同：

| 数据关系 | 想说的话 | 推荐图型 |
|---|---|---|
| **对比** | 谁大谁小 | 柱状图、条形图、雷达图、排行榜 |
| **趋势** | 随时间怎么变 | 折线图、面积图、瀑布图 |
| **构成** | 整体由哪几块拼成 | 饼图、堆叠柱状图、旭日图 |
| **分布** | 数值落在哪些区间 | 直方图、箱线图、热力图 |
| **关联** | 两个量之间有关系吗 | 散点图、气泡图、桑基图 |

编辑器内置 18 种图 + KPI 卡片（合起来 19 个样式），每种都标了它属于哪一类关系，选图时按关系找，而不是按长相找。

### 7.2 维度个数决定能选哪些图

这是最容易被忽略的一条约束：**不是所有图都能画两个维度**。

| 维度数 | 图形家族 | 可选样式 |
|---|---|---|
| 0 维 | KPI 卡片 | KPI |
| 1 维 | 单系列：一个维度决定横轴 | 13 种：柱状、条形、雷达、排行、折线、面积、瀑布、饼图、直方图，以及只有示例数据能画的箱线、散点、气泡、桑基 |
| 2 维 | 交叉：两个维度决定横轴和系列 | 5 种：分组柱状、多系列折线、堆叠柱状、热力图、旭日图 |

所以界面的行为是：**先勾维度，样式列表跟着过滤**。勾了 2 个维度，"饼图"就消失（饼图表达不了两个维度）；退回到 1 个维度，"分组柱状图"就消失。这不是限制，是防错——把画不出来的选项藏起来，比画出来是错的要好。

### 7.3 维度增减时的"同族迁移"

有一种顺序需要特别处理："先选好样式、再改维度"。如果此时简单地把选项重置成列表第一个，明明选了折线，改成 2 维就变回柱状图——直觉上像是"我的选择丢了、白选了"。

这里采用**同族迁移**：能在同一语义家族里找到对应的两维版本，就迁移过去，保不住才回落。

| 原样式（1 维） | 加维度后（2 维） | 逻辑 |
|---|---|---|
| 柱状图 / 条形 / 雷达 / 排行 / 直方 | 分组柱状图 | 都是"比大小"，加一个维度就成分组 |
| 折线 / 面积 / 瀑布 | 多系列折线 | 都是"看趋势"，加一个维度就成多条线 |
| 饼图 | 旭日图 | 都是"看构成"，加一个维度就成两层环 |

反方向同理：2 维退回 1 维，分组柱→柱状、多线→折线、旭日→饼图。

### 7.4 只开放"真能算出来"的样式

有些图看着漂亮，但**用聚合后的数据根本画不出来**：

| 样式 | 需要什么 | 为什么真算给不了 |
|---|---|---|
| 箱线图 | 每组的原始分位数 | 聚合只留了求和 / 平均，中位数、四分位已经丢失 |
| 散点图 / 气泡图 | 同一行上的两个度量 | 一次只算一个度量，凑不出 (x, y) 点对 |
| 桑基图 | 节点之间的流向与流量 | 需要"从哪到哪"的关系列，普通事实表没有 |

这三种如果硬开放，选了之后只能被迫画成柱状图，结果是**选择了 A、得到 B、还不知道为什么**——这是最需要避免的一种状态。

所以规则是：**只把能真实渲染的 14 种样式放进自定义指标的可选列表**，画不出来的不出现。示例数据那条链路不受此限，18 种全开（它的数据是按图形形态构造的，形态齐全），两条链路各管一段。

### 7.5 两条链路：示例数据 vs 真实计算

| | 示例数据 | 真实计算 |
|---|---|---|
| 触发条件 | 用的是内置占位指标，或没导入表 | 自定义指标 + 有效事实表 |
| 数值来源 | 按图形形态构造的随机数 | 从明细表真实聚合 |
| 用途 | 排版、配色、演示形状 | 真实汇报 |
| 图上标注 | 标题后缀"示例数据" | 无 |

两条链路**完全隔离**：真实计算这条路，只有在数据和配置都齐备时才进入；任何一步算不出来，就退回示例数据并在标题上标注。这样永远不会出现"图上是一堆看着像真的、实际是编的数"——混淆真实与示例，是数据大屏最不能犯的错。

### 7.6 维度与形状就在列表里改，不必重新钻取

一个已经上屏的指标，临时想"换个维度看看"或"从柱图改成饼图"，都不该再走一遍五步配置。所以列表行内直接给了两组入口：

| 入口 | 位置 | 作用 |
|---|---|---|
| 展示形式胶囊 | 行内第 4 列 | 只换形状（KPI / 柱 / 折线 / 饼…），点一下立刻重绘大屏 |
| 维度胶囊 | 行内第 2 行 | 加/减维度，样式按"同族迁移"自动跟着变 |

这里有一条硬约束：**改了必须立刻重绘**（详见 8.4）。列表和大屏是同一份状态的两个视图，任何一边改了、另一边没跟上，用户就会开始怀疑"到底哪个算数"。

## 八、布局引擎：40 张卡怎么自己站好位置

### 8.1 一切尺寸都用"逻辑像素"

大屏要投到 1920 的会议屏、3840 的拼接屏、也可能在笔记本上给客户看。如果按屏幕像素排布，换一块屏全乱。

做法是把画布当成一张固定高度的**设计稿**：高度恒为 900，宽度可配（1600–4000），所有卡片坐标都写在这套逻辑坐标里；显示时整体等比缩放：

```
缩放比 = 屏幕可用宽度 / 画布逻辑宽度        （宽度适配）
缩放比 = 屏幕可用高度 / 900                  （高度适配）
```

整块画布一次性乘上这个系数，**卡片之间所有相对关系不变**，所以 3200 宽的设计稿在 1920 屏上显示，除了整体变小，位置关系一模一样。适配方式可切：宽度适配保证横向铺满（上下可能留边），高度适配保证纵向铺满（左右可能留边）。

### 8.2 两种骨架，先决定大屏长什么样

| 骨架 | 结构 | 适合 |
|---|---|---|
| **A 型** | 左图表带 — 中间三维区 — 右图表带 | 三维场景是主角，图表左右护卫 |
| **B 型** | 三维区在左 — 图表带在右 | 图表多，三维作为背景故事 |

分区的宽度不是随便分的，是按比例算出来并带可行性校验的：

```
A 型：单侧带宽 = min( (画布宽 − 980) / 2 , 画布宽 × 25% )
      要求 单侧带宽 ≥ 290，中心区 ≥ 900，否则判定"当前参数不可行"
      图表带总宽 = 2 × 单侧带宽

B 型：中心区宽 = max( 900 , 画布宽 − 924 )
      图表带宽 = 画布宽 − 56 − 中心区宽
      要求 图表带宽 ≥ 262
```

`(画布宽 − 980) / 2` 保证中心区至少留 900 多给三维场景；`画布宽 × 25%` 则是防止超宽屏（比如 4000）时侧带无限膨胀、把中间挤没。两个上限取小，是"既要够用、又不失控"。

### 8.3 卡片总数与列数的求解

卡片总数是乘法出来的：

```
A 型：卡片数 = 2 × 列数 × 行数      （左右两条带，各 列数 × 行数）
B 型：卡片数 = 列数 × 行数
```

行数只有两档（紧凑 3 行、宽松 2 行），列数在 1–4 之间**自动求解**。求解用的是"宽高比逼近"：

```
对 n = 1, 2, 3, 4 依次试：
    列宽 cw = ( 可用带宽 − (n−1) × 16 ) / n
    若 cw < 236  →  停止（再分就太窄，图里塞不下坐标轴）
    宽高比 r = cw / 行高
    打分 score = | r − 1.5 |
    若 r < 0.86  →  额外罚分 (0.86 − r) × 4   （太竖长的卡片很难看）
取分数最低的 n
```

为什么目标是 **1.5**：这是图表卡的"舒服比例"——横向略宽于高，能放下一个横轴 + 四五个刻度 + 图例，既不空旷也不局促。为什么下限有两条（列宽 ≥ 236、宽高比 ≥ 0.86）：前者保证基本可读，后者保证不会出现一根细长条。

行高档位与对应卡片高度：

| 密度 | 行数 | 卡片高度 | 适用 |
|---|---|---|---|
| 紧凑 | 3 行 | 236 | 指标多，一次性铺满，一目了然 |
| 宽松 | 2 行 | 362 | 重点突出，每张图信息量更大 |

算出来的结果会先在配置弹窗里**预览**，可行就用，不可行会直接提示"请调整宽度或密度"——不会提交一个自己都摆不平的方案。

### 8.4 改了就必须立刻重绘：一个"数据对、画面不动"的教训

曾经出过一个只影响观感、却让人完全不信任工具的 bug：点样式按钮，列表里的"柱状"变成"饼图"、内部状态也真的变成了饼图，**但大屏上还是柱状图**。

根因不在渲染层（14 种样式逐个实测都能画对），而在于改动只走到了"状态"，没走到"渲染"：三个改动作（改样式 / 改维度 / 改汇总方式）只更新了配置对象和列表行，没有人去调重绘。

修法的关键不是"在三个地方各补一行重绘"，而是**把重绘收敛成一个入口**（同一帧内多次改动只画一次，避免连续拖拽时反复重建图表）。之后任何改动只要碰了配置，就必须经过这一个入口，从此不会再漏。

这条规矩值得单独写下来：**界面上任何一处"看起来该变"的东西，都必须在同一次操作内变完。** 用户不会去分辨"是状态错了还是渲染错了"，他只会得出一个结论——这工具不靠谱。

## 九、KPI 横排：一行大数字怎么排

### 9.1 为什么要单独设计

KPI 卡是"一眼看到的大数字"，它的可读性完全取决于**字号**，而字号取决于卡片宽度。所以 KPI 不能像图表那样随便塞进格子，必须保证每张都有足够宽度。

如果 KPI 竖排在三维区左侧的窄带上，卡片只有 210 宽、54 高，字号会被压到 10–11px——本该最醒目的元素，反而成了全场最小的字，同时挡住三维场景左侧一条竖带。**横排占图表带顶部一行**之后：每张 180–380 宽，字号能放大一倍以上，三维区完整露出。

### 9.2 张数上限是算出来的，不是写死的

大屏宽度是可配的，能放几张必须现场算：

```
单张最小宽 = 180
KPI 行间距 = 12

最多张数 = max( 2 ,  ⌊ ( 带宽 + 12 ) / ( 180 + 12 ) ⌋ )
```

这条公式的含义：把带宽按"每张 180 + 间隔 12"去切，能切几份就是几张。分子多加一个 12，是补偿最后一张后面不需要间隔——不加这一步会少算整一张。

每张实际宽度再均分一次，并守住下限：

```
每张宽 = max( 180 , ⌊ ( 行宽 − 12 × (张数−1) ) / 张数 ⌋ )
```

为什么下限是 **180**：低于这个宽度，标题会折行、数值要缩到 20px 以下，KPI 就失去了"远远看一眼就知道"的意义。宁可少放两张，也不放一排读不清的小字。

以 3200 宽的 A 型为例，图表带 768 宽：

| KPI 张数 | 均分下来每张宽度 | 是否达标（≥180） |
|---|---|---|
| 2 | 378 | ✅ |
| 3 | 248 | ✅ |
| 4 | 183 | ✅ 刚好 |
| 5 | 144 | ❌ 不够 180，所以上限公式只放到 4 张 |

### 9.3 行高：给图表让出 100px

KPI 行高固定 **88**，行与图表之间留 **12**，合计占掉 100px。内容区高 784，紧凑 3 行的卡片高度因此从 251 降到 217——这是横排的代价，换来的是 KPI 可读性翻倍、三维区完整露出。

### 9.4 两种模式：参与排版 / 不参与排版

| 模式 | 一键排版时对 KPI 做什么 | 适合 |
|---|---|---|
| **参与** | 先横排占住带顶一行，然后变成"障碍物"，图表从它下面开始排 | 想让整版一次归位 |
| **不参与** | 只做轻量对齐（顶边齐平 + 间距均分），位置和尺寸基本不动，图表绕开它 | 已经手工摆好了，只想微调 |

两种模式是同一个开关控制的，状态会记住，下次打开还是上次的选择。

## 十、手动干预：拖了就要对齐

自动排版解决 80% 的情况，剩下 20% 靠手。手拖最大的问题是"差 3px 看不出来但很丑"，所以给了三类辅助。

### 10.1 吸附：8px 之内自动贴

拖动时，卡片有 6 个锚点：左 / 中 / 右 三条竖线，上 / 中 / 下 三条横线。画布另外提供 6 条参考线：左边界、水平中线、右边界，以及上边界、垂直中线、下边界。

规则：拖动中的任何一个锚点，与任何一条候选线距离 ≤ **8px**，就吸附过去，并画一条黄色对齐线提示"贴到了谁"。

```
候选竖线 = { 画布左 0, 画布中线, 画布右 } ∪ { 其他每张卡的 左 / 中 / 右 }
候选横线 = { 画布上 0, 画布中线, 画布下 } ∪ { 其他每张卡的 上 / 中 / 下 }
选距离最近的那一条，且必须 ≤ 8px
```

8px 这个阈值是手感和精度的平衡：太小贴不上，太大会"粘住"手感。

### 10.2 两套对齐，分工不同

| 功能 | 参照物 | 改哪些轴 | 典型场景 |
|---|---|---|---|
| **九宫格对齐** | 选中多张卡的**整体外框** | 同时改 X 和 Y | 把 4 张散乱的卡归成一个整齐的块 |
| **单轴对齐**（6 个方向） | 选中项里的**第一张**（基准卡） | 只改一个轴，另一轴纹丝不动 | 三张卡左边缘要对齐，但高低要保留错落 |

单轴对齐的 6 个方向分两组：**左、垂直中线、右**——作用在 X 轴上，卡片只左右移动；**上、水平中线、下**——作用在 Y 轴上，卡片只上下移动。

这里"垂直中线"指一条竖着的中线，让各卡片的水平中心对齐到同一条竖线上；"水平中线"指一条横着的中线，让各卡片的垂直中心对齐到同一条横线上。

基准卡的判定：多选时先点的那张。它会被标一个黄色外框加"基准"角标，避免"点了右对齐，结果整体飞到了别处"——**对齐一定是往某个东西上靠，必须让人看得见靠的是谁**。

### 10.3 一键排版的三条分支

一个按钮背后是三个判断，按顺序走：

```
分支 1｜只选了 ≥2 张卡
    → 轻量路径：这几张列内左对齐 + 间距均分，整体原地不动

分支 2｜全部卡：已有明显的列结构（卡片虽歪但纵向成列）
    → 就地整理：只在每一列内部做顶底对齐 + 间距均分，不动整体位置

分支 3｜全部卡：卡片扎堆、没有列结构
    → 重排：按带宽切成 4 列平摊，三维区保持原位
```

两条硬约束贯穿全程：

1. **任何两张卡不许重叠**。排完做一次全量重叠检测，一旦发现压住，**整版回滚**，不做"改一半"；
2. **改之前先进撤销栈**，`Ctrl+Z` 可以一步步退回。而且只有真的移动了才进栈——空点一下按钮不会污染历史。

### 10.4 容量就是卡片数，不另设参数

有一类设计会把"最多能放几个指标"做成一个独立设置项（`maxIndicators = 12`）。这个参数看起来灵活，实际一定会和布局打架：布局算出 12 张卡，参数写着 20，第 13~20 个指标就会"上屏了但不显示"。

所以这里干脆不设这个参数——**容量 = 当前布局的卡位数**，现算：

| 布局 | 图表位 | KPI 位 |
|---|---|---|
| A 型（带两侧带宽） | `2 × 列数 × 行数` | 3 |
| B 型（中间单带宽） | `列数 × 行数` | 3 |
| 自由布局 | 图表卡张数 | KPI 卡张数 |

好处是**只有一个真源**：改布局，容量自动跟着变，不需要用户去同步第二个数字。代价是改布局会"缩容"，可能砍掉已上屏的图——所以 17.2 那三道护栏必须存在。

## 十一、保存与交付：为什么坚持单文件

| 关注点 | 做法 | 好处 |
|---|---|---|
| 部署 | 一个 HTML 文件，双击即开 | 没有安装、没有服务、没有端口 |
| 依赖 | 图表引擎、地图底图、全部样式都内嵌 | 断网也能跑，内网也能跑 |
| 存档 | 浏览器本地存储，机器本地 | 数据不外传，符合内网要求 |
| 迁移 | 程序本身拷走即用；数据留在本机浏览器里 | 给客户演示只要一个 U 盘，现场导数据 |
| 编辑/放映 | 同一份文件：编辑态所见，即放映态所得 | 不存在"设计稿和成品不一致" |

代价也要说清楚：本地存储意味着**换浏览器、换电脑、清缓存都会丢**，拷走 HTML 文件不会带走数据和配置。所以它适合"设计 + 演示"，不适合当长期数据看板——长久方案是把导出的配置和数据结构接进正式系统。

## 十二、能力边界

明确不做的，比做了的更能说明定位：

| 不做 | 原因 | 暂时怎么办 |
|---|---|---|
| 行级/时间范围筛选 | 单文件原型，全量计算 | 导入前先在 Excel 筛好 |
| 多表关联（JOIN） | 无数据库，也没必要在大屏里做 | 在源头拼成一张宽表 |
| 一个图里两个度量（散点/气泡） | 计算只出一个度量 | 用双图并排表达 |
| 箱线图、桑基图（真算） | 聚合后丢失分位数 / 流向 | 用直方图、堆叠图近似 |
| 权限、多人协作 | 单机工具 | 定位为"个人设计器" |
| 数据定时刷新 | 无后端 | 重新导入文件 |

这些不是"以后要做"，而是**在当前形态下主动放弃**——每加一条，就离"双击即用、断网能跑"更远一步。

## 十三、分享时怎么讲（5 分钟脚本）

1. **先给结论**（30 秒）：一个 HTML 文件，把明细表变一面大屏，离线可用。
2. **演四级流水线**（2 分钟）：导入一张 768 行的表 → 配一个"按区域求和"的指标 → 看预览表里的数字 → 上屏出图。
3. **演防错**（1 分钟）：故意拿"单据号"当维度，勾选框是灰的并提示"超限"——说明它不是"能用就行"，而是"知道什么不该用"。
4. **演维度联动**（1 分钟）：加第二个维度，饼图消失、分组柱状图出现；把维度减回去，又变回饼图——样式没丢，只是换了个族。
5. **演排版**（1 分钟）：一键排版 → 拖歪两张 → 按单轴对齐 → 展示基准卡角标和黄色吸附线。

## 十四、界面骨架：一个弹窗只分五块

编辑器只有一个主弹窗，但它的信息密度极高：左侧要放数据、右侧要放图，中间还要能"边配边看"。所以骨架不能靠堆卡片，只能**分层**——每一层只回答一个问题：

| 层 | 位置 | 回答的问题 |
|---|---|---|
| 外壳 | 弹窗头 + 标签栏 + 底栏 | 我现在在哪个工作面？还剩几个位？ |
| 指标管理 | 中间列表 | 哪些指标在屏上、在第几位、长什么样？ |
| 维度计算（钻取） | 覆盖层 | 这个指标的数是怎么算出来的？ |
| 文案配置 | 左右两栏 | 标题、菜单长什么样？ |
| 数据管理 | 三段 | 有哪些表、谁在用、能不能删？ |

### 14.1 外壳：用量必须"随手能看到"

一个指标上屏，会同时受三处约束：图表位、KPI 位、已上屏总数。如果这三个数只在某一页的某个角落出现，用户就必须"翻页核对"，这是最容易出错的地方。

解决办法是**同一组数字重复三处，且都由同一个函数算**：

```
弹窗头副信息   图表位 4/12 · KPI 位 1/3 · 已上屏 5 个指标
标签徽章       数据管理 8   /   指标管理 6
底栏进度条     KPI 1/3 [====----]   图表 4/12 [========--]
```

四处（含底部数字）永远一致，因为它们不是各自维护状态，而是每次计数变化时从同一处重算后一起刷新。

### 14.2 底栏两根进度条：满位和超位不是一回事

进度条的橙色只表示一件事——**没余量了**。所以判断用的是 `已用 ≥ 总数` 而不是 `已用 > 总数`：

| 状态 | 数字颜色 | 进度条 | 含义 |
|---|---|---|---|
| 未满（3/12） | 蓝 | 蓝色，25% | 还能加 |
| 满位（12/12） | 橙 | 橙色，100% | 再加就放不下，得先撤一个 |
| 超位（14/12） | 橙 | 橙色，100% | 状态异常，只可能出现在布局刚被改小之后 |

为什么满位就变橙？因为用户在这个位置上的下一个动作必然是"再加一个"。**在没有余量时不提醒，等加不进去了才提醒，就等于没提醒。**

### 14.3 指标管理：列表必须像表格，不能像聊天记录

指标列表一行要装下五类信息：上屏状态、名称与口径、位次、展示形式、操作。信息越多，越需要**列对齐**——否则每行都在不同位置，扫视成本会指数上升。

所以这一块定了一条硬规矩：**表头是固定的一行，而不是每行自带标题**。五行列（上屏 44 / 指标·口径 自适应 / 位次 92 / 形式 240 / 操作 86）用同一套宽度定义，表头与行内元素的左边缘误差控制在 2px 内（实测 1px）。

行内再折成两行：第一行是"这是什么指标"（角标 · 名称 · 模块），第二行是"它是怎么算的"（数据表 · 聚合 · 度量 · 单位 ｜ 维度胶囊）。两行的分工是固定的，扫一眼就知道该看哪行。

### 14.4 上屏用开关，不用按钮

这里有一个反直觉的取舍：**开关和按钮不是审美差别，是语义差别。**

- 按钮（上屏/下屏）表达"动作"，用户要先判断当前状态，再点对应的按钮；
- 开关表达"状态"，当前状态和操作入口是同一个东西，点一下就翻转。

大屏位次本质是一种**状态**（在屏上/不在屏上），所以用开关。但只保留开关会带来另一个问题——上一版曾经做过"点样式即上屏"，结果用户找不到"到底怎么上屏"。所以最终形态是：**开关负责在不在，胶囊只管长什么样**，两件事绝不混用。

### 14.5 分组：自定义和示例不能混在一起

列表里同时存在两类指标：用户自己算出来的（可编辑、可删）、内置示例（只读）。它们混排会出现两种误解——"示例能改吗"、"我删的到底是不是自己的"。

所以列表固定两段，组头各带计数与自己的动作：

| 组 | 组头动作 | 为什么 |
|---|---|---|
| 自定义指标 N | + 新建指标 | 新建属于"我的指标"，不属于整个页面 |
| 示例指标 N | 恢复已隐藏示例（N） | 示例是内置的，**隐藏**比删除更诚实——删了清缓存还是会回来 |

顺带一个词的选择：示例只给"隐藏/恢复"，不给"删除/恢复"。因为"删除"承诺了不可逆，而内置数据做不到这个承诺。

### 14.6 钻取：五步要能"看见自己在第几步"

配一个指标是五个步骤，用户最怕的不是步骤多，而是**不知道还剩几步、走错了要不要重来**。所以钻取层做了三件事：

1. **横向 stepper**：五步均分、编号圆、已走过打勾变绿、当前项下划蓝线，且可点跳转；
2. **右侧摘要栏**（288px，sticky）：六~七行配置摘要随当前步骤高亮，随时能确认"我前面填的是什么"；
3. **固定底部工具条**：不论滚到哪里，`取消 / 上一步 / 下一步 / 保存并上屏` 都在原位。

摘要行与步骤的对应关系是硬绑定的，**每一步都必须有主**：第 1 步认领事实表与名称，第 2 步认领字段角色，第 3 步认领维度与度量，第 4 步认领粒度，第 5 步认领展示形式。曾出现过第 2 步没有任何一行高亮的情况，右栏看起来像"死"了——这不是小瑕疵，用户会以为界面卡住。

### 14.7 数据管理：先导入，再看已有，最后才是危险操作

三段顺序不能反：

```
导入区（三宫格）  →  已导入表（7 列表格）  →  清空全部数据（红色危险区）
```

- **导入在最上面**，因为进这一页的人 80% 是来导数据的；
- **表格 7 列**（表名 / 行数 / 列数 / 被引用 / 来源 / 导入时间 / 操作），其中"被引用"是删除前的判断依据——被指标引用的表，删了会让指标变成"数据表已删除"；
- **清空全部数据放最底下并标红**，且它是数据的事，不该出现在文案配置页（曾经放错了地方）。

"导入"给了三条路，因为现实里数据就是从三个地方来的：

| 入口 | 真实场景 | 处理 |
|---|---|---|
| 上传文件 | 手里有 csv/tsv 导出件 | 按首行表头解析，自动推断列角色 |
| 粘贴数据 | 从 Excel 里复制一片 | 同上，行尾空行自动丢弃 |
| 示例数据 | 手上暂时没数据，先看效果 | 代码内置 72 行演示表，不依赖任何外部文件 |

第三条容易被当成"玩具"，但它决定了**第一次打开的人能不能在 30 秒内看到一张图**——空状态留白是最大的流失点。

## 十五、三个入口与一层钻取

弹窗只有三个平级入口（文案配置 / 数据管理 / 指标管理），"维度计算"不是第四个标签，而是从指标管理**钻进去**的一层。

### 15.1 为什么维度计算不做成第四个标签

如果它是平级标签，用户必须先想"我要配指标，该点哪个标签"，而他往往是从列表里某一行出发的——**入口应该是那一行，不是标签栏**。

于是定了规则：

| 行为 | 从哪进 | 退出后回到哪 |
|---|---|---|
| 新建指标 | 自定义组头的 `+ 新建指标` | 指标管理（新指标已上屏，行高亮） |
| 编辑指标 | 行尾 `编辑` | 指标管理（同一行） |

钻取期间标签栏**被面包屑替换**（`← 指标管理 / 新建指标`），这样"我在第二层"这件事不需要靠记忆维持；点标签栏则等于放弃草稿，直接退回第一层。

### 15.2 只钻一层，不能再钻

钻两层的代价是用户会迷路，收益却很小。所以规则是：**钻取层里不再出现任何"更深一层"的入口**，所有子配置都在五步里用内联控件完成（下拉、勾选、文本框）。宁可一步里控件多一点，也不让人再点一次"进入配置"。

## 十六、菜单 3–8 与按菜单隔离

大屏顶部有若干菜单（总览 / 分析 / 药品……），每个菜单是**一套独立的布局 + 一套独立的图表**，不是同一套数据的过滤视图。

### 16.1 数量为什么是 3 到 8

| 边界 | 原因 |
|---|---|
| 下限 3 | 少于 3 个不需要菜单栏，直接一屏讲完；且 1~2 个会让页签显得多余 |
| 上限 8 | 页签宽度有限，超过 8 个必然换行或缩字，识别成本陡增；同时 8 套布局已超出单人维护的合理范围 |

点"1"会被夹到 3，点"9"直接拒绝——**不是弹个错就完事，而是按钮本身就点不动**，从源头消除非法状态。

### 16.2 隔离意味着什么

隔离不是"复制一份"，而是"各存各的账"：

| 数据 | 是否按菜单隔离 | 说明 |
|---|---|---|
| 布局（卡位、类型、行数） | 是 | 每个菜单各一套 |
| 已上屏指标与位次 | 是 | 同一指标可以在 A 菜单当 KPI、在 B 菜单当柱图 |
| 数据表 | 否 | 数据是全局的，换菜单不该重新导入 |
| 指标定义 | 否 | 指标是"算法"，与摆在哪个菜单无关 |

这条边界很重要：**数据和指标是资产，布局和上屏是陈列**。资产共享、陈列隔离，才能在"加一个菜单"时不用重导数据。

### 16.3 切菜单必须有入口

设计稿里没有"正在配置：某菜单"的切换条，但这一条不能照抄——因为隔离之后，用户必须能明确知道"我现在改的是哪个菜单的图"。所以指标管理顶部保留一条菜单切换条，并把当前布局类型（如"A 型 2×3×2：12 图表位 · 3 KPI 位"）一并显示，避免"改完发现改错了菜单"。

## 十七、即时生效与容量护栏

### 17.1 没有"确定/取消"，只有"关闭"

弹窗里的每一处改动（改样式、切维度、开关上屏、改文案）都**立刻写入并立刻重绘**，`×` 只是关窗，不是撤销。

这么定有两个理由：

1. 大屏是"边改边看"的活，如果要点确定才生效，用户会陷入"改一下—确定—看—再改"的循环；
2. "取消"承诺的是"回到打开前"，而多轮改动后这个语义很难自洽（改了三处，取消一处算不算取消？）。

代价是误操作会直接生效，所以补偿手段是**可逆**：样式随时能改回、上屏随时能关、指标能编辑。**能被改回来，就不需要撤销。**

按这个原则，"取消"按钮被删掉了——留着它反而暗示"改动没生效"。

### 17.2 容量 = 卡片数，不是"感觉差不多"

一张大屏能放几个指标，是布局算出来的，不是拍脑袋定的：

```
A 型：图表位 = 2 × 列数 × 行数（如 2×3×2 = 12），KPI 位固定 3
B 型：图表位 = 列数 × 行数（如 2×2 = 4）
自由布局：图表位 = 图表卡数，KPI 位 = KPI 卡数
```

容量必须在三处同时可见（14.1 已述），因为**它会被布局改动影响**。于是有三个必须处理的时刻：

| 时刻 | 现象 | 处理 |
|---|---|---|
| 上屏时位次已满 | 点了开关但没位置 | 弹橙色提示，给一个「用本指标替换某个示例」的可点出路 |
| 布局从 A 型切成 B 型 | 12 位变 4 位，多出的 6 张图无处安放 | 立刻按新容量裁剪，并在行内标红「超出 05」 |
| 超出后 | 屏幕上看不到、列表里还在 | 顶部给一键收起，收起后回到容量内 |

关键是第三条：**超出的指标不能静默消失**。如果只在屏幕上少几张图、列表里毫无标记，用户会以为"上屏失败"。所以超位次必须有明确的红色标签 + 一个一键处理的按钮。

### 17.3 展示形式要记住"上次是什么样"

同一个指标，关掉再打开，形状不应该变。所以每个指标记忆自己上次的展示形式；只有从未上屏过的指标，才按"维度个数 → 推荐样式"的规则给默认值。

这一条看起来是小细节，但它决定了用户敢不敢反复开关——**如果每次打开形状都变，用户就不敢关，也不敢试。**

### 18.1 一条反复验证过的经验

五轮里最贵的一课发生在第五轮：**把设计稿当成"功能清单"去实现，结果功能都在、长相全错。**

设计稿承载的信息有两层——"要有什么能力"（容易提取）和"摆在什么位置、什么形态、什么顺序"（容易被丢掉）。后者不是审美，它本身就是产品决策：表头决定扫视成本、开关决定语义、分组决定归属、底部固定条决定"敢不敢走错"。

所以现在的做法是：**设计稿先转成"差距总表"（逐条写 设计稿长什么样 / 现状长什么样 / 判定），再动手。** 这张表同时是实施清单和验收清单——改完对着它一条条打勾，比凭印象验收可靠得多。

## 附：核心公式速查

| 环节 | 公式 |
|---|---|
| 指标 | `指标(S) = 聚合{ 度量(r) \| r ∈ S }` |
| 求和 | `Σ mᵢ` |
| 平均 | `Σ mᵢ / n`（n = 有效行数） |
| 计数 | `n`（行数，文本列亦可） |
| 分组数 | `c₁ × c₂ × … × cₖ` |
| 维度可用 · 类目上限 | `C ≤ 30` |
| 维度可用 · 非唯一 | `C / N < 0.9`（或全表 ≤ 30 行） |
| 缩放比 | `屏幕宽 / 逻辑宽` 或 `屏幕高 / 900` |
| A 型带宽 | `min( (W−980)/2 , 0.25W )`，且 ≥ 290 |
| B 型带宽 | `W − 56 − max(900, W−924)`，且 ≥ 262 |
| 列宽 | `(带宽 − 16(n−1)) / n`，且 ≥ 236 |
| 列数选择 | 取 `\|列宽/行高 − 1.5\|` 最小者，宽高比 < 0.86 罚分 |
| 卡片数 | A 型 `2×n×m`；B 型 `n×m` |
| KPI 张数上限 | `max(2, ⌊(带宽+12)/192⌋)` |
| KPI 单张宽 | `max(180, ⌊(行宽 − 12(n−1))/n⌋)` |
| 吸附阈值 | 锚点与候选线距离 ≤ `8px` |
| 图表位容量 | A 型 `2×n×m`；B 型 `n×m`；自由布局 = 图表卡数 |
| KPI 位容量 | A/B 型固定 `3`；自由布局 = KPI 卡数 |
| 满位判据（进度条变橙） | `已用 ≥ 总数` |
| 超位判据（位次标红） | `已用 > 总数` |
| 菜单个数 | 夹在 `[3, 8]`，越界时按钮点不动 |
| 表头对齐误差 | 表头与行内 5 列的 `左边缘` 差 ≤ `2px` |
